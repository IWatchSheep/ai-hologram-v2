WHAT 4c'S RUN WITH FAULTS CONTAINS (the rest is added later)
The plan's 3.6 describes the finished run. In 4c, leave out everything that
belongs to the scorer (4d) and the observer (4e):
  - the activation hook is only injector.atActivationPoint(parts, t);
  - afterDecision / afterFinalCheck only call the extra watchers;
  - there is no observe flag yet and no observer is attached;
  - FaultRunResult holds the RunResult exactly as runSingleAgent returned
    it, decisionSteps and the activation records (scores come in 4d,
    observed evaluations in 4e);
  - FaultRunWatchers (afterDecision and afterFinalCheck) and
    NaiveFaultRunWatchers (afterDecision) receive the agent, the
    observation (and the decision for afterDecision) and the injector, as
    const references; the scorer argument is added in 4d.
Everything else is as 3.6: onObservation appends every observation to the
run's true history (the injector reads it for F5); after runSingleAgent
returns, the hook is emptied.

DETAILS
A. onObservation (3.12): RunWatchers gets a third member and
   NaiveRunWatchers a second, std::function<void(const SingleAgent&,
   const Observation&)> / std::function<void(const NaiveAgent&,
   const Observation&)> onObservation, called with every observation just
   before the agent receives it: before every decide, and before C1's
   finalCheck. An empty one is not called. Nothing else in the loop changes
   (continueRun passes it on like the other watchers).
B. fault_model: FaultedActions (which actions are faulted and each one's
   rotation, indexed by actionIndex), rotatedAction (left N->W->S->E->N,
   right N->E->S->W->N), makeFaultyModel(table) taking a COPY of the table,
   exactly as plan 3.4 and ref_faults.make_faulty_model.
C. fault_apply: ReasonerParts (belief, action model, "not dead" overrides,
   predictor, as references), partsOf(SingleAgentState&),
   partsOf(NaiveAgentState&), ApplyOutcome {applied, reason}, and
   tryApplyFault(event, parts, faultedActions, trueHistory), exactly as plan
   3.4 and ref_faults.try_apply_fault: the checks in that order, the exact
   reason texts, F1 flips only inside the grid, F5's previous square from the
   TRUE history, clearCache() after every applied fault and never after a
   refused one. It never touches the world or a budget. Use the shared names

   no new copies (R4).
D. fault_injector: ActivationStatus (Scheduled, Applied, NotApplicable,
   Pending), ActivationRecord {eventId, type, scheduledStep, status,
   applicationStep, reason}, activationDelay, reportedAs (the five exact
